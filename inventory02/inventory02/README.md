# inventory02 — Классы, объекты и инкапсуляция

Вариант: А · Воин, лимит массы 6000 г.
Начальные предметы: Меч (weapon, 2500 г, 100), Щит (armor, 3000 г, 80), Зелье (potion, 500 г, 20).

## Структура

- `kz.javaworkshop.Item` — неизменяемая модель предмета (`src/main/java/kz/javaworkshop/Item.java`)
- `kz.javaworkshop.Inventory` — модель рюкзака с инвариантами по ячейкам и массе (`src/main/java/kz/javaworkshop/Inventory.java`)
- `kz.javaworkshop.Main` — консольное меню, точка входа (`src/main/java/kz/javaworkshop/Main.java`)

## Запуск

```
mvn compile exec:java
```

Требуется JDK 21 и Maven 3.9+.

## Результаты проверок

1. Заполнение до точного лимита. Меч (2500 г) + Щит (3000 г) + Зелье (500 г) = 6000 г из 6000 г,
   ячеек занято 3/4, стоимость 200. Все три `add()` вернули `true`.
2. Два отказа.
   - Добавление предмета массой 1 г сверх оставшегося лимита (после заполнения до 6000/6000) →
     `add()` вернул `false`, содержимое инвентаря не изменилось.
   - Отдельный инвентарь с 1 ячейкой на 100 г: первый предмет 1 г добавлен успешно, второй
     предмет 1 г отклонён из-за нехватки ячеек (`false`), размер остался 1.
3. Удаление со сдвигом и использование зелья.
   `remove(0)` удаляет Меч, Щит и Зелье сдвигаются на позиции 1 и 2, `size()` становится 2.
   Использование зелья (`type == "potion"`) удаляет предмет и печатает «Зелье использовано»;
   попытка использовать оружие как зелье ничего не меняет.
4. Независимость снимка.
   `snapshot()` возвращает новый массив; замена его первого элемента на `null` не влияет на
   исходный `Inventory` — метод `get(0)` по-прежнему возвращает исходный предмет, поскольку
   копируются только ссылки на неизменяемые объекты `Item`, а не сам внутренний массив.

## Бонусные операции

- `Inventory.findByName(String query)` — регистронезависимый поиск по подстроке имени,
  возвращает новый массив найденных предметов (пункт меню «6 поиск по имени»).
- `Inventory.transferTo(Inventory target, int index)` — перенос предмета между двумя рюкзаками:
  если целевой рюкзак отказывает (`add` вернул `false`), исходный рюкзак не изменяется.
